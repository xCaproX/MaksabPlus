# مكسب بلس — نظام إدارة المبيعات والمخزون والحسابات (MaksabPlus)

نظام سحابي متكامل وسريع للمنشآت الصغيرة والمتوسطة: فواتير المبيعات والمشتريات والمرتجعات والهالك، إيصالات الاستلام والصرف (تلقائية وحرة)، تحويلات المخازن والخزن، كشوف الحسابات اللحظية، وإدارة صلاحيات المستخدمين، مع بنية معمارية فائقة السرعة تدعم مئات الآلاف من السجلات دون المساس بالأداء.

- **الواجهة:** React + Vite + TypeScript، عربي RTL مع تصميم متجاوب لكافة الشاشات.
- **قاعدة البيانات:** Supabase (PostgreSQL 15+ مع Auth و RLS متعدد المستأجرين Multi-Tenant).
- **العملة:** جنيه مصري (ج.م).

## 1. قاعدة المنطق والأثر المالي والمخزني

| العملية | رمز المستند | التأثير على رصيد الحساب | التأثير على المخزون | التأثير على الخزنة |
|---|---|---|---|---|
| فاتورة مبيعات | `SAL` | + إجمالي الفاتورة (مديونية) | − كميات السطور المباعة | — |
| فاتورة مشتريات | `PUR` | + إجمالي الفاتورة (مستحقات للمورد) | + كميات السطور المشتراة | — |
| مرتجع مبيعات | `SRT` | − إجمالي المرتجع | + كميات السطور المرتجعة | — |
| مرتجع مشتريات | `PRT` | − إجمالي المرتجع | − كميات السطور المرتجعة | — |
| فاتورة هالك | `WST` | — (لا تؤثر على حساب العميل/المورد) | − كميات السطور التالفة | — |
| إيصال استلام | `RCP` | − قيمة الإيصال (سداد مديونية) | — | + قيمة الإيصال |
| إيصال صرف | `PAY` | − قيمة الإيصال (سداد مستحق) | — | − قيمة الإيصال |
| تحويل مخزني | `WTR` | — | − من المصدر / + إلى الهدف | — |
| تحويل نقدي | `CTR` | — | — | − من المصدر / + إلى الهدف |

### القواعد الحسابية والتشغيلية:
1. **الأثر المالي المتكامل والمعاملات المتبادلة (المقاصة):**
   - معادلة رصيد الحساب اللحظي:
     - **لحساب العميل:** الرصيد = رصيد أول المدة + (المبيعات + مرتجع المشتريات) − (المشتريات + مرتجع المبيعات) − (إيصالات الاستلام − إيصالات الصرف).
     - **لحساب المورد:** الرصيد = رصيد أول المدة + (المشتريات + مرتجع المبيعات) − (المبيعات + مرتجع المشتريات) − (إيصالات الصرف − إيصالات الاستلام).
   - التعاملات المتبادلة (المقاصة): عند بيع بضاعة لمورد تنخفض مستحقاته، وعند شراء بضاعة من عميل تنخفض مديونيته، مع اتساق رياضي تام بين الأرصدة اللحظية وكشوف الحسابات التفصيلية.
   - في المرتجع ذي المسترد النقدي: المسترد يعكس أثره على الخزنة مباشرة عبر إيصال معاكس تلقائي، ويبقى صافي مديونية الحساب مطابقاً للواقع.
2. **استقلالية الحساب عن نوع المستند:**
   - يمكن البيع أو الشراء من أي حساب سواء كان مصنفاً كعميل أو كمورد. نوع الفاتورة هو المحدد الصارم لحركة المخزون والخزنة، بينما يتحدد اتجاه الأثر المالي وفق طبيعة الحساب.
3. **متوسط التكلفة المتحرك والربحية التلقائية:**
   - يُحسب متوسط تكلفة الصنف آلياً لكل مخزن مع كل عملية شراء أو رصيد أول مدة.
   - تُثبت تكلفة الوحدة وقت إنشاء الفاتورة، وتُحسب التكلفة الإجمالية والربح وتُخزن في جدول الفواتير لضمان سرعة الاستعلام العالية.
4. **الأرصدة اللحظية (Running Balances):**
   - ترتبط الحسابات والخزن بتريجرات قاعدة بيانات تحدث الرصيد اللحظي `current_balance` فور كل حركة، مما يمنع استعلامات الجمع الثقيلة مع تضخم البيانات.
5. **منع الأرصدة السالبة في المخزن والخزنة:**
   - يمنع النظام صرف أو بيع أو تحويل أي كمية تتجاوز الرصيد الفعلي المتوفر في المخزن المحدد، كما يمنع أي صرف نقدي أو تعديل أو حذف أو تحويل نقدي يكسر رصيد الخزنة إلى السالب (`insufficient_cash_box_balance`).
6. **دعم الكسور العشرية وتوقيت القاهرة الموحّد:**
   - يدعم النظام الكميات العشرية (أوزان بالكيلوجرام، أطوال بالأمتار) بدقة `numeric(18,4)`، ويعتمد توقيت مصر المحلي (`Africa/Cairo`) عبر `cairo_today()` في كافة التواريخ الافتراضية ومؤشرات لوحة التحكم.

## 2. المعمارية وقابلية التوسع (Scalability Architecture)

تمت ترقية النظام ليعمل بنمط معالجة جهة الخادم (Server-Side Architecture) لتحمل مئات الآلاف من الفواتير والعملاء والأصناف:

1. **تصفح الصفحات على السيرفر (Server-Side Pagination):**
   - جميع الجداول (الفواتير، الإيصالات، التحويلات، العملاء، الموردين، الأصناف، أرصدة المخازن والخزن) تستعلم بنطاق محدد (`.range(from, to)`) بمعدل 20 سجلاً لكل صفحة، مما يمنع الاصطدام بحد الـ 1000 سجل في PostgREST أو استهلاك ذاكرة المتصفح.
2. **المؤشرات التجميعية الذكية (RPC Aggregation Functions):**
   - يتم حساب مؤشرات الأداء (KPIs) في شريط كل شاشة عبر دوال قاعدة بيانات مخصصة (`SECURITY DEFINER`) تنفذ التجميع الرياضي (`sum`, `count`, `avg`) مباشرة داخل محرك Postgres دون جلب السجلات للواجهة.
3. **البحث الثلاثي فائق السرعة (GIN Trigram Indexes):**
   - استخدام ملحق `pg_trgm` لإنشاء فهارس GIN على الأسماء، والأكواد، وأرقام الهواتف، وأرقام الفواتير لضمان تنفيذ عمليات البحث النصي الجزئي في أجزاء من المللي ثانية.
4. **تسطيح المجاميع الحسابية (Denormalization):**
   - إلغاء الربط الجانبي (`lateral join`) في عرض الفواتير `v_invoice_list` والاعتماد على قراءة مباشرة لأعمدة التكلفة والربح المحدثة بالتريجر.

## 3. صلاحيات المستخدمين (Granular RBAC)

نظام أذونات أمني دقيق ومحكم (للمزيد راجع [الخريطة المعمارية](docs/architecture/README.md)):
- مستويات التحكم: **عرض**، **إضافة**، **تعديل**، **حذف** لكل قسم ولكل تبويب فرعي.
- إخفاء وإظهار أعمدة الأرباح والتكلفة الحساسة بناءً على إذن صريح (`reports.profit.view`)، وحجب سعر الشراء (`purchase_price`) في عروض المخزون لغير المصرح لهم عبر `can_view_purchase_price()`.
- حماية على مستويين:
  1. **مستوى الواجهة (UI Guards):** إخفاء الأزرار والأقسام المحظورة عبر خطاف `useAccess()` ودالة `can()`.
  2. **مستوى قاعدة البيانات (Database RLS & Functions):** رفض أي عملية غير مصرح بها برموز خطأ قياسية، مع فرض الصلاحيات الدقيقة داخل دوال البيانات الأساسية والافتتاحيات وكشوف الحسابات.

## 5. التشغيل والتطوير المحلي

### المتطلبات:
- Node.js (الإصدار 18 أو 20 أو 22).
- مشروع Supabase.

### خطوات التثبيت:
```bash
# 1. تثبيت الحزم
npm install

# 2. إعداد متغيرات البيئة
copy .env.example .env.local
# ثم املأ VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY

# 3. تشغيل خادم التطوير
npm run dev
```

### تشغيل الاختبارات:
```bash
# تشغيل كافة اختبارات قاعدة البيانات (65 ملف اختبار SQL في بيئة PGlite معزولة)
npm run test:db

# تشغيل اختبارات الواجهة والوحدات (Vitest) واختبارات إدارة المستخدمين والتحقق
npm test

# فحص صحة وتكامل قاعدة بيانات Supabase الحية عن بُعد
npm run db:verify-remote
```

## 7. هيكل الملفات البرمجية

```text
supabase/
  functions/          # دوال Edge Functions (مثل manage-users)
  migrations/         # كافة ملفات الهجرة الـ 80 مرتبة تسلسلياً
  tests/              # 65 ملف اختبار SQL ومحاكي PGlite المحلي واختبارات Node
  verify-remote-db.mjs # محرك التحقق الآلي من تكامل قاعدة البيانات البعيدة
docs/
  architecture/       # التوثيق المعماري الحي للمشروع (نظرة عامة، قاعدة البيانات، المنطق، الواجهة، الأمان)
  screenshots/        # لقطات شاشات التطبيق لتوثيق وتأكيد واجهات الاستخدام بمقاسات RTL
scripts/              # سكريبتات فحص الواجهة، التزامن، وفلاتر الأعمدة
src/
  components/         # المكونات المشتركة (DateInput, DateDisplay, MoneyDisplay, KpiBar, StatusBadge, ...)
    charts/           # مكونات الرسوم البيانية التفاعلية (Chart.js) وخطوط النبض (Sparklines)
    invoice-form/     # مكونات نموذج الفاتورة الموحد (رأس الحساب، جدول البنود، الملخص)
  context/            # سياق إدارة البيانات الأساسية (MasterDataContext)
  lib/                # دوال المعالجة الحسابية، التنسيق، الصلاحيات، الاتصال بـ Supabase، والتحقق
  pages/              # شاشات التطبيق:
    home/             # مكونات لوحة التحكم الرئيسية (بطاقات المبيعات، النبض المالي، القوائم الأعلى)
    balances/         # شاشة الأرصدة (حسابات، خزن، أصناف)
    master-data/      # شاشة البيانات الأساسية (عملاء، موردون، أصناف، مخازن، خزن)
    receipts/         # شاشة الإيصالات والتحويلات النقدية (مفككة لوحدات مستقلة)
    invoices/         # جداول ومؤشرات الفواتير والتحويلات المخزنية
    management/       # تبويبات الإدارة والأرصدة الافتتاحية وسجلات المطابقة
    Home.tsx          # الشاشة الرئيسية ولوحة التحكم
    Invoices.tsx      # شاشة الفواتير والتحويلات المخزنية
    Receipts.tsx      # شاشة الإيصالات والتحويلات النقدية
    MasterData.tsx    # شاشة البيانات الأساسية
    Balances.tsx      # شاشة الأرصدة وكشوف الحسابات
    Management.tsx    # شاشة الإدارة والمستخدمين والصلاحيات
```

## 8. ما هو غير موجود بعد (متعمد ومخطط له مستقبلاً)

- الخصم التجاري أو ضريبة القيمة المضافة على مستوى بنود الفاتورة.
- تعدد العملات (النظام يعمل حالياً بالجنيه المصري).
- نقاط البيع المتزامنة Offline (بدون إنترنت).
